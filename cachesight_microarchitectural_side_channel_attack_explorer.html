Hardware Vulnerability & Timing Attacks

How CPU Speed Optimizations Secretly Leak Private Passwords

Modern CPUs use extremely fast internal memory called Caches to store frequently accessed data. However, reading from a Cache takes ~2 nanoseconds, while reading from Main RAM takes ~100 nanoseconds. Attackers can exploit this timing difference to reconstruct secret cryptographic keys without ever reading the memory directly!

Concept Deep Dive

Understanding the Flush + Reload Attack Mechanics

How an isolated, unprivileged attacker process extracts secrets across security boundaries.

1

Flush Phase

The attacker issues the clflush instruction to evict all shared memory lines from the CPU cache back into main RAM.

2

Victim Phase

The victim executes its algorithm (e.g. RSA decryption or lookup table). It accesses specific memory addresses depending on its secret key.

3

Reload / Probe

The attacker measures access time for each shared memory line using CPU high-resolution timers (rdtsc).

4

Secret Deduction

Fast access (~2ns) = Cache Hit! The victim touched that line. Slow access (~100ns) = Cache Miss. The secret is deduced!

❌ Algorithmic Complexity Vulnerability: O(Value)

In naive table lookups, memory execution time scales depending on input value secrets: array[secret_byte]. This creates an unintentional timing side-channel observable by external processes.

✅ Constant-Time Defense Mitigation: O(1)

Secure cryptographic code uses constant-time algorithms. By executing uniform bitwise arithmetic operations without branching or table lookups, access times remain identical regardless of secret key values.
